# v0.6.2 RDB、异步快照、混合恢复与性能门禁

## 范围与并发模型

v0.6.2 保持单线程 Level-Triggered epoll Reactor。AOF writer pthread 与每次最多一个
BGSAVE 子进程是唯二后台执行单元；不引入 io_uring、多线程 Reactor、向量检索、
负载均衡、分片、复制或集群。

`SAVE` 是有意保留的同步管理命令：RDB 序列化、fdatasync、rename 和目录 fsync
全部完成后才返回，因此会阻塞 Reactor。它只用于维护、故障诊断和确定性功能测试，
不进入 QPS 对照。生产与自动快照只使用 `BGSAVE`。

## KVRDB001

文件由固定 8 字节魔数 `KVRDB001`、大端整数头、对象记录、结束标记和大端 CRC64
组成。CRC64 使用 ECMA 多项式 `0x42f0e1eba9ea3693`，覆盖 footer 之前的全部字节。

头部依次记录快照 Unix 毫秒、记录数、AOF 检查点偏移、检查点有效位和 16 字节随机
令牌。每条记录包含对象类型、绝对 TTL、二进制安全 key 和对象内容：String 保存
原始字节，Hash 保存 field/value，ZSet 保存 member 与 IEEE-754 score 位模式。加载
时可选择 SkipList 或 RBTree，因而两个后端可以交叉恢复。加载会丢弃已到期 key，
拒绝未知魔数/版本、未知类型、非法 score、CRC 错误、截断、长度溢出、重复成员以及
记录数不一致。

保存写入同目录唯一临时文件，依次执行 fdatasync、close、原子 rename 和父目录
fsync；序列化或写盘失败会删除临时文件，不主动覆盖已有快照。

## BGSAVE 一致性屏障

命令在 Reactor 内建立短屏障，因此屏障期间不会执行新的写命令：

1. AOF 开启时生成 16 字节随机令牌，追加标准 RESP2 `PING <hex-token>`。
2. 等待该序列完成 write 和 fdatasync，并记录标记末尾的绝对 AOF 字节偏移。
3. 请求 AOF writer 到达条件变量安全点；writer 不持有生产者/屏障 mutex 执行
   fdatasync。
4. fork 后父进程立即恢复 writer 和 Reactor；子进程关闭继承的网络、epoll、timer、
   eventfd 和 AOF fd，只读遍历 fork 时刻的 Cache 并保存 RDB。
5. 父进程周期性使用 `wait4(..., WNOHANG)` 收割子进程。成功时只减去 fork 时覆盖的
   dirty 数，保留快照期间的新写；失败保留旧快照和 dirty 数。

`INFO PERSISTENCE` 报告 dirty、BGSAVE 状态、最近结果/持续时间、检查点偏移、屏障与
fork 暂停、子进程峰值 RSS/minor/major faults，以及 AOF write/sync 序号、队列、
fdatasync 次数/总耗时/最大耗时。minor faults 是 COW 活动的诊断代理，不等同于精确
COW 字节；Redis 对照额外记录其 `rdb_last_cow_size`。

## 恢复规则

- 仅 AOF：从字节 0 完整回放。
- 仅 RDB：校验并加载快照，忽略其中仅供混合模式使用的检查点元数据。
- RDB+AOF：RDB 必须带有效检查点；AOF 在记录偏移之前必须存在完全相同的 PING
  令牌。验证后从偏移开始回放尾部。
- 任意令牌、偏移、CRC 或格式不匹配均拒绝启动，不静默回退。

本版不做 AOF rewrite，也不实现 Redis RDB 或单文件混合 AOF 格式；检查点之前的
AOF 历史继续保留。

## 性能改动与门禁

请求命令只识别一次，按长度常量分派。无 TTL 的条目不读取实时时钟；容量限制均为
0 时不维护 LRU。Hash/ZSet 修改复用首次顶层查询得到的 entry handle，ZADD score
使用 service 固定数组。Socket recv 和 RESP 编码直接使用连接 Buffer 的
reserve/commit 窗口。AOF writer 用 writev 合并批次，在 fdatasync 期间不持有生产者
mutex，并按批次通知 eventfd。AOF 的 enqueued/written/synced 序号、错误和背压状态
使用 C11 原子发布；Reactor 私有 producer chunk 只在满 256 KiB 或批次 flush 时进入
writer 队列，避免每条写命令争用 writer mutex。Helgrind 构建只对这些 C11 原子存储
增加 Valgrind 注解，生产构建不依赖 Valgrind。writer 在回收已写 chunk 的同一次
临界区内发布 written sequence，避免完成路径重复获取队列锁。`everysec` 使用持续
推进的 CLOCK_MONOTONIC 绝对截止时间；新数据唤醒 writer 不会重置一秒周期，持续
写负载下仍会执行 fdatasync。

动态 Hash 的字节散列保留 FNV 乘法与最终 avalanche，但改为四路独立累加器，缩短
64B ZSet member 的串行乘法依赖链。Hash 命令另外使用一个由 Cache 持有的热顶层 key
entry；删除、过期和淘汰在释放 entry 前统一失效该引用。String 和 ZSet 顶层查找仍走
原路径，避免给随机 key 或已验证的 ZSet 路径增加额外比较。ZSCORE 与 ZRANGE
WITHSCORES 对可精确往返的一位小数使用无分配整数格式化快路径，其余 double（包括
负零和特殊边界）继续使用 `%.17g`，保持恢复与协议精度。

正式矩阵固定 Redis 6.2.23、同一 C 客户端、同机同盘、32 连接、100,000 keyspace、
64B payload、每单元 10,000,000 请求、5 轮中位数。P16/P64 是门槛；String、Hash、
ZSet 均为 90% 读/10% 写，覆盖 off、everysec、everysec+BGSAVE。QPS 变异系数超过
5% 的整组作废。普通和 BGSAVE 单元都要求 0 error、cardinality 正确、项目 QPS 不低
于 Redis 且 P99 不高于 Redis；项目 everysec 相对 off 的 QPS 损失不超过 5%，P99
增幅不超过 10%。

SkipList/RBTree 先按 P16/P64、off/everysec 四组 ZSet mixed 的几何平均 QPS 选择；
差异不超过 1% 时保留 SkipList。`bench/v062_release_gate.py` 实施该选择和严格门禁。
任何门槛未通过都不得创建 v0.6.2 tag/Release。仓库不记录未经目标 Ubuntu 实测的
QPS 或延迟数字。
