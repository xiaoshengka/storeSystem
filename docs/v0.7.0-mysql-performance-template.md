# v0.7.0 MySQL 性能报告

> 本文件只记录实测结果。未执行项填写“未测试”，不得用估算值替代。

## 环境

- 日期与版本：2026-08-22；`v0.7.0`
- Ubuntu / kernel：VMware Ubuntu；精确版本/kernel 未随结果同步
- CPU / vCPU / 绑核：8 vCPU；未绑核
- 内存：12 GB
- 磁盘、文件系统、虚拟化：VMware；磁盘与文件系统未记录
- GCC、编译参数、allocator、`MYSQL=1` 客户端版本：Makefile 默认 `-O2`、jemalloc；
  精确 GCC/libmysqlclient 版本未随结果同步
- MySQL Server 版本、buffer pool、redo/binlog、数据目录：MySQL 8.0.46；buffer pool
  不在轮次间清空；其余未记录
- 客户端/服务/MySQL 所在主机：同一 Ubuntu VM，TCP loopback
- AOF 路径、fsync 策略：每轮临时空 AOF，`everysec`；计时负载为只读 GET

## 固定 workload

- 32 个持久连接，Pipeline=1，64B String value。
- 100,000 个唯一 key，每轮 100,000 次 GET，所有请求均为 kvstore 内存冷 miss。
- 客户端、kvstore 与 MySQL 位于同一台 VMware Ubuntu 虚拟机。
- MySQL/InnoDB buffer pool 不在轮次间清空，因此不代表数据库冷盘读取。
- 共 5 轮，报告中位数并保留全部逐轮结果；任何返回值、回源计数或队列校验失败都不
  计入有效结果。

执行命令：

```bash
python3 bench/mysql_cold_miss_bench.py \
  --requests 100000 --connections 32 --pipeline 1 --repeats 5 \
  --output bench/result/v0.7.0-mysql-cold-miss.csv
```

| 场景 | 并发 | Pipeline | value | QPS 中位数 | P99 中位数 | 校验 |

| String 全量冷 key miss | 32 | 1 | 64B | 26,868.13 | 1.965 ms | PASS |
