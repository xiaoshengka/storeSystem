# v0.6.1 性能验证报告

## 1. 测试范围与口径

本报告记录 v0.6.1 在正式目标环境中的 64B Hash/ZSet mixed 长测结果，只比较
v0.6.1 与 Redis 6.2.23，不运行 v0.6.0。

- 环境：VMware Ubuntu 22.04.5，8 核 CPU，12 GB 内存，客户端与服务端同机。
- 构建：GCC `-O2 -g -Wall -Wextra -Wpedantic`，项目默认链接 jemalloc；Redis
  6.2.23 使用 jemalloc 5.1.0。
- 并发：32 条连接，Pipeline 16。
- 数据：共享 keyspace 100,000，payload 64B，确定性 seed 20260820。
- 请求：每轮 10,000,000 次；Hash 为 90% HGET / 10% HSET，ZSet 为
  90% ZSCORE / 10% ZADD。
- 后端：项目 Hash、SkipList ZSet、RBTree ZSet，以及对应 Redis Hash/ZSet。
- 策略：AOF off、AOF everysec；每组 9 轮，表中为逐轮结果的中位数。
- 正确性：全部错误数为 0，实际 cardinality 均为 100,000，项目 AOF 背压次数为 0。

输入摘要文件为 `hash-zset-mixed-long.csv.summary.csv`，SHA-256 为
`DA9645B64D65A2F8A871DB33A30C71B03BE886E89FAE904C30D03A7577527928`。

百分比口径：

```text
QPS 损耗 = (off QPS - everysec QPS) / off QPS
P99 增幅 = (everysec P99 - off P99) / off P99
项目相对 Redis QPS = (项目 QPS / Redis QPS) - 1
项目相对 Redis P99 = (项目 P99 / Redis P99) - 1
```

负的 QPS 损耗只表示两组独立测量的 everysec 中位数略高，应按测试波动解释，
不表示持久化提升了性能。

## 2. off 到 everysec 的开销

| 实现 | workload | off QPS | everysec QPS | QPS 损耗 | off P99 (us) | everysec P99 (us) | P99 增幅 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Hash | 90% HGET / 10% HSET | 657,326.68 | 660,960.61 | -0.55% | 1,172.671 | 1,158.736 | -1.19% |
| SkipList | 90% ZSCORE / 10% ZADD | 567,485.20 | 566,981.04 | 0.09% | 1,343.839 | 1,587.837 | 18.16% |
| RBTree | 90% ZSCORE / 10% ZADD | 569,626.73 | 570,550.36 | -0.16% | 1,333.901 | 1,572.330 | 17.87% |

结论：三个项目后端的 everysec QPS 损耗均在 1% 以内，达到不超过 5% 的目标。
Hash 的 P99 未出现可测损耗；SkipList/RBTree 的 P99 分别增加 18.16% 和
17.87%，超过不高于 10% 的目标。两种 ZSet 后端的 P99.9 还分别增加 32.20% 和
31.08%，说明 writer 周期同步期间仍存在明显尾延迟。

## 3. v0.6.1 相对 Redis 6.2.23

| policy | workload/实现 | 项目 QPS | Redis QPS | QPS 差异 | 项目 P99 (us) | Redis P99 (us) | P99 差异 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| off | Hash | 657,326.68 | 839,605.13 | -21.71% | 1,172.671 | 1,066.738 | 9.93% |
| off | SkipList ZSet | 567,485.20 | 642,256.61 | -11.64% | 1,343.839 | 1,276.835 | 5.25% |
| off | RBTree ZSet | 569,626.73 | 642,256.61 | -11.31% | 1,333.901 | 1,276.835 | 4.47% |
| everysec | Hash | 660,960.61 | 787,949.74 | -16.12% | 1,158.736 | 1,137.830 | 1.84% |
| everysec | SkipList ZSet | 566,981.04 | 646,995.77 | -12.37% | 1,587.837 | 1,287.254 | 23.35% |
| everysec | RBTree ZSet | 570,550.36 | 646,995.77 | -11.82% | 1,572.330 | 1,287.254 | 22.15% |

结论：Pipeline 16 下，项目 AOF off 的核心 workload QPS 比 Redis 低
11.31%～21.71%，未达到差距不超过 5% 的目标。everysec 下 Hash 的 P99 已接近
Redis，但吞吐仍低 16.12%；两种 ZSet 的吞吐低约 12%，P99 高约 22%～23%。

SkipList 与 RBTree 基本持平：RBTree 在 off/everysec 下的 QPS 分别高约 0.38% 和
0.63%，不足以认定某个有序索引显著更优。共同瓶颈更可能位于 member Hash、命令
服务、LRU/统计以及 RESP 编解码热路径。

## 4. 验收结论

| 验收项 | 目标 | 结果 | 状态 |
| --- | --- | --- | --- |
| 正确性 | 0 error，cardinality 正确 | 全部满足 | 通过 |
| AOF 背压 | 正式 workload 不触发高水位 | 0 次 | 通过 |
| everysec QPS 损耗 | 不超过 5% | -0.55%～0.09% | 通过 |
| everysec P99 增幅 | 不超过 10% | Hash -1.19%；ZSet 17.87%～18.16% | ZSet 未通过 |
| AOF off 相对 Redis QPS | 差距不超过 5% | 低 11.31%～21.71% | 未通过 |

截至本次测试，v0.6.1 的功能、正确性和 AOF 吞吐目标已形成闭环，但性能发布门槛
尚未全部满足。根据项目 Release 规则，本结果可以提交到功能分支留档，但不能据此
创建正式 `v0.6.1` tag/GitHub Release。后续应优先 profile Hash mixed 公共热路径，
并记录 fdatasync 持续时间与响应屏障等待时间，定位 ZSet everysec 尾延迟。
