# v0.6.1 内存热路径与异步 AOF

## 范围

v0.6.1 保持单线程、Level-Triggered epoll Reactor。AOF 使用一个 pthread writer；
不引入多线程 Reactor、io_uring、RDB、BGSAVE 或混合加载。默认构建通过 pkg-config
强制链接 jemalloc；`ALLOCATOR=libc` 只用于诊断和资源检查。

## 内存热路径

- 动态 Hash 使用 64 位 FNV-1a 和 avalanche finalizer。slot 数保持二次幂，桶定位
  使用位掩码；每次请求只计算一次 hash，并在渐进 rehash 中快速跳过连续空桶。
- Hash 节点的元数据和二进制 key 一次分配；String 对象和数据一次分配；Hash field
  value 使用 flexible array，容量足够时原地覆盖。内存统计按实际保留容量计费。
- ZADD 更新已有 member 时先从 SkipList/RBTree 摘除原节点，更新 score 后重新插入，
  不重新分配 ordered node。RBTree 重插前重置 parent/child/color/subtree_size。
- RESP 与 AOF 的整数和长度头使用边界检查后的手写十进制编码。

## AOF writer

命令执行期间的所有 AOF 记录（包括淘汰产生的 DEL）先写入 transaction buffer，
一次 commit 后按同一序号进入队列。队列由 256 KiB 可复用粒度的 chunk 组成，高/低
水位为 4 MiB/2 MiB；高水位期间新写命令返回可重试错误，读命令仍可执行，日志不被
静默丢弃。writer 每轮最多用 16 个 iovec 合并 `writev`。

普通写完成后 writer 发布 written sequence，并写 Reactor 的 eventfd。连接输出缓冲
记录本批响应所需的最大 sequence；在 sequence 完成前不注册 EPOLLOUT，因此成功
响应不会先于普通 AOF write 发出。`always` 在 fdatasync 后才发布完成；`everysec`
由同一 writer 最多约每秒 fdatasync；`no` 不做周期同步。

启动回放使用只读 mmap 和 `MADV_SEQUENTIAL`，仍由严格 RESP2 parser 校验。仅末尾
不完整帧会截断修复，中间损坏会使启动失败。`INFO PERSISTENCE` 暴露队列字节数、
高低水位、enqueued/written/synced sequence、累计写入字节、背压次数和错误状态。

## 可复现验证

在线脚本固定 32 连接，`--pipelines` 默认 16，也支持逗号列表。每个 target、AOF
policy、workload、ZSet backend 和 pipeline 独立记录五轮及汇总；不跨 pipeline
计算中位数。只比较当前 v0.6.1 与 Redis 6.2.23，不运行 v0.6.0。

AOF 重放脚本覆盖 String/Hash/ZSet 的 10,000、100,000、1,000,000 条命令，默认
五轮，记录启动可用时间、纯 replay、commands/s、MiB/s、CPU、VmHWM、文件大小与
正确性，并把首轮和后续轮次分组。未经 Ubuntu 22.04.5 正式环境实测，不填写 QPS、
延迟或重放性能数字。已完成的 64B mixed 长测数据、计算口径和未通过门槛见
[`v0.6.1-performance-report.md`](v0.6.1-performance-report.md)。
