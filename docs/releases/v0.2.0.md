# v0.2.0 Non-blocking epoll Reactor

v0.2.0 将项目默认网络路径从 NtyCo 原型切换为单线程、非阻塞、
Level-Triggered epoll Reactor，同时保持 v0.1.0 的文本命令和三种内存引擎兼容。

## 主要变更

- 提供 Reactor 初始化、运行、停止、销毁和事件增删改接口。
- 使用 `epoll_event.data.ptr` 关联动态连接对象，移除按 fd 索引的超大静态数组。
- 每个连接拥有独立输入/输出缓冲区、读写位置和生命周期状态。
- 监听和客户端 Socket 全部非阻塞，处理 `EINTR`、`EAGAIN`、EOF 和致命错误。
- 仅在存在待发送数据时监听 `EPOLLOUT`，支持部分写并保留发送偏移。
- 统一处理 `EPOLLERR/HUP/RDHUP`、half-close、SIGPIPE 和连接资源回收。
- 网络层通过请求回调进入服务层，不直接依赖具体 KV 引擎。
- 新增缓冲区与 KV 单元测试、Reactor 集成测试、ASan/Valgrind 目标和并发 QPS 客户端。
- 默认构建生成 `kvstore`、`legacy_client` 和 `qps_client`；NtyCo 通过 `make ntyco`
  单独构建。

## 验证与性能基线

目标验收环境为 VMware Ubuntu 22.04.5、8 核 CPU、12 GB 内存。构建使用 Makefile
默认选项 `-O2 -g -Wall -Wextra -Wpedantic`，验证入口包括：

```bash
make clean && make
make test
make integration-test
make asan
make valgrind
```

QPS 客户端和服务端同机运行，使用 32 条持久 TCP 连接执行命中 `HGET`，每连接预热
1000 次。计时阶段完成 1,000,000 / 1,000,000 次请求，用时 13.745987 秒，测得
72,748.50 QPS，TCP_NODELAY 开启。该数字是上述环境和工作负载下的一次实测基线，
不代表其他环境或负载下的峰值。

## 已知限制

- v0.2.0 暂时把一次可读批次视为一条完整文本命令。
- 尚不支持 RESP、增量解析、可靠的半包/粘包处理或 Pipeline；这些属于 v0.3.0。
- 尚不支持 TTL/LRU、AOF 或 MySQL Cache-Aside。
- Reactor 为单线程 LT 模型，不包含 ET、多线程 Reactor 或 io_uring。

Reactor 的完整工作流和状态机见
[`docs/reactor-v0.2.md`](../reactor-v0.2.md)。
