# v0.7.0 MySQL Cache-Aside

发布日期：2026-08-22。

## 版本概述

v0.7.0 在 v0.6.2 的单线程 epoll Reactor、String/Hash/ZSet、TTL/LRU、AOF 和 RDB
基础上增加可选 MySQL Cache-Aside。MySQL 默认关闭；开启后作为最终数据层，内存
Cache 与 RDB/AOF 作为热快照。写成功仍以本地修改和 AOF 写入完成为边界，MySQL
随后由后台单 writer 按 mutation sequence 异步落库，不新增独立 WAL。

## 主要变更

- Reactor 支持请求挂起、异步完成回调和 eventfd 唤醒；单连接最多挂起一个请求，
  保持 Pipeline 响应顺序。
- 默认 8 个独占连接的读线程并行回源，单个 writer 严格有序提交；工作线程只执行
  SQL，不访问 Cache、AOF 或连接对象。
- String、Hash、ZSet 和顶层 TTL 支持完整对象回源；依赖旧状态的冷 key 写命令先
  回源再执行。
- 同 key 并发 miss 合并为一次查询；独立空值缓存默认保存 3 秒、最多 10,000 key，
  写入时立即失效。
- 每条实际生效的 AOF mutation 后追加 `PING KVMYSQL1:<uuid>:<seq>`，用于启动时
  对账和补投；MySQL 事务同时更新业务表、change log 与 writer 水位。
- 首次启用支持把 RDB+AOF 恢复对象及绝对 TTL 灌入空数据库；MySQL 水位落后时补投，
  领先时根据 change log 失效旧热快照。
- 运行期数据库故障时，未过期缓存命中继续服务，miss 返回明确错误；写队列达到高
  水位后返回 `TRYAGAIN`，不返回过期数据。
- 新增版本化 schema、MySQL CLI 配置、`INFO MYSQL` 指标、部署文档、集成测试与
  全量冷 key miss 基准脚本。

## 验证结果

- `MYSQL=0` 的 unit、integration 与 benchmark smoke 路径未发现回归。
- MySQL 集成测试通过，覆盖三种对象、二进制数据、TTL、LRU 淘汰后回源、空值缓存、
  首次灌库、数据库领先 AOF 恢复和冷 key 写入。
- VMware Ubuntu、8 vCPU、12 GB 内存、MySQL 8.0.46，客户端/kvstore/MySQL 同机；
  32 并发、64B value、Pipeline=1、100,000 个唯一冷 key，每轮 100,000 次 GET，
  连续 5 轮全部校验通过。

| 轮次 | QPS | P99 |
| ---: | ---: | ---: |
| 1 | 26,491.81 | 1.965 ms |
| 2 | 27,525.39 | 1.850 ms |
| 3 | 26,987.51 | 1.973 ms |
| 4 | 26,868.13 | 1.901 ms |
| 5 | 23,343.86 | 2.179 ms |
| **中位数** | **26,868.13** | **1.965 ms** |

发布指标可概括为：在 32 并发、64B value、Pipeline=1、全量冷 key miss 条件下，
MySQL 回源吞吐约 26.9K QPS，P99 延迟约 1.97 ms（5 轮中位数）。这里的冷 key
只表示 kvstore 内存 Cache 为空；MySQL buffer pool 未清空。

## 部署

服务不会自动执行 DDL。管理员需先执行 `config/mysql-v0.7.0.sql`，为服务账号授予
目标库的 SELECT、INSERT、UPDATE、DELETE 权限，并通过 `KVSTORE_MYSQL_PASSWORD`
传入密码：

```bash
make MYSQL=1
export KVSTORE_MYSQL_PASSWORD='replace-me'
./kvstore --appendonly yes --appendfsync everysec \
  --mysql yes --mysql-host 127.0.0.1 --mysql-port 3306 \
  --mysql-user kvstore --mysql-database kvstore
```

完整 schema、首次灌库、恢复及故障语义见
[`docs/v0.7.0-mysql-cache-aside.md`](../v0.7.0-mysql-cache-aside.md)。

## 已知限制

- 仅允许本服务写业务表，不支持外部 SQL 写入、CDC/binlog 订阅或多 writer 实例。
- 不实现 AOF rewrite；MySQL mutation 使用现有 AOF 标记恢复，不新增 WAL。
- 冷 miss 数据只适用于上述同机、Pipeline=1、MySQL 热 buffer pool 场景，不外推到
  冷盘、跨机或生产容量结论。
- io_uring、分片、复制和集群不属于本版本范围。
