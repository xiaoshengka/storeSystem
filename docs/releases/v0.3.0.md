# v0.3.0 RESP2 and Pipeline

v0.3.0 为 epoll 主服务增加严格的 RESP2 子集、增量解析和 Pipeline，并把 Hash 与
RBTree 接入同一套二进制安全命令服务。Array、NtyCo 和旧文本命令仅保留为历史
对照，不再由 epoll 主服务暴露。

## 主要变更

- 只接受 RESP2 `Array of Bulk Strings`，拒绝 inline、嵌套类型、Null Bulk、非法
  数字和错误 CRLF。
- 增量解析半包并保留未消费数据，可从同一输入批次拆分多个粘连请求。
- 按请求顺序生成 Pipeline 响应，复用非阻塞部分写和 `EPOLLOUT` 状态机。
- 设置 1 MiB 单连接输出高水位，积压时暂停读取，排空后继续处理缓存请求。
- 统一支持 `SET/GET/DEL/PING`，命令名使用 ASCII 大小写不敏感匹配。
- Hash/RBTree 新增长度感知接口，支持空 key/value 和嵌入 `NUL`。
- 通过 `./kvstore --engine hash|rbtree` 选择后端，默认使用 Hash。
- `qps_client` 改用 RESP2，并支持 `-P 1..1024` 配置 Pipeline 深度。

## 协议限制与错误语义

- 单帧最大 64 KiB，最多 128 个参数。
- 非法、超限或 EOF 时仍不完整的帧返回 `-ERR Protocol error\r\n`，响应发送完成
  后关闭连接，避免在损坏字节流中重新同步。
- 未知命令、参数数量错误和内部错误使用统一 RESP Error 回复。

## 验证

本阶段在 Ubuntu 环境完成以下验证：

```bash
make test
make integration-test
make asan
make valgrind
make ntyco
```

Hash 与 RBTree 均通过单元和集成测试；ASan/UBSan 与 Valgrind 未发现新增内存错误
或泄漏。`qps_client` 已在两种引擎下完成 `-P 1` 和大于 1 的功能性 smoke test。
本版本不把短时 smoke test 的瞬时 QPS 作为正式性能结论。

## 已知限制

- 主服务仍是单线程、Level-Triggered epoll Reactor。
- Hash 仍使用固定槽位，不包含动态扩容。
- TTL/LRU、AOF、MySQL Cache-Aside、集群和复制不属于本版本。

协议、命令和背压设计详见 [`docs/resp-v0.3.md`](../resp-v0.3.md)。
